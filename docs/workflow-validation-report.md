## 自动化证据

已使用独立 PostgreSQL 16、Redis 和真实 systemd user＋bubblewrap worker 运行 `scripts/test-integration.sh`（`go test -race -count=1 ./...`）。没有使用现有服务数据库或全局 Redis 来代替独立测试。

新增用例覆盖：v2 与布局 CAS、原快照在编辑/关闭后继续执行、计划时间跨日业务日期、同步/异步/定时 API＋代码链、部署只编译、样本不调用 provider 或创建 operation、viewer 权限、原子赋值失败、条件汇合与短路、大数精确比较、禁用 due 项不堵 LIMIT、固定 cutoff 恢复及重复维护。完整 C1 链使用三个上游 API 分别提供单价/数量/优惠，代码计算 1900 后向订单 API 传参；三个入口共调用 12 次 API，定时运行排队跨日仍保留计划业务日期。代码开关关闭后，代码样本拒绝，含代码草稿内的普通处理样本仍可执行。

沙箱测试实际检查非特权身份、零 capability、NoNewPrivs、隔离网络/文件系统、128 MiB 内存和零 swap；覆盖 1900 金额计算、ID 关联、按客户汇总、结构转换、输入副本、不执行顶层代码的部署、空对象、异常/非法 JSON、时钟禁用、动态构造禁用、栈限制、死循环/native allocation、取消与失败后可继续启动新 worker。无法确认 OOM 原因时为 worker_failed，未伪称已识别内存原因。
