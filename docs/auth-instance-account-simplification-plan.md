# 认证实例与账号创建流程精简开发方案

状态：功能已实施并补齐复核发现的遗漏（2026-10-02），本地检查通过；数据库集成、真实上游认证与运行服务更新仍待验收。本文记录目标方案、实现边界与验证结果。

日期：2026-10-02。依据当前工作区源码编写；工作区已有大量未提交修改，实施时以现有代码为基线，不覆盖其他工作。

## 1. 目标与推荐决策

用户在添加认证实例时填写一次真实账号凭据，点击“保存并验证”，即可得到可供 API 使用的连接。无需再进入连接账号页面完成三步向导。

推荐采用以下方案：

1. 将认证实例编辑器现有“真实认证测试”区改为“连接账号”，复用现有凭据字段组件。
2. 在同一表单增加 API 基础地址，自动创建集成配置与首个连接账号。
3. 保留后台认证实例、集成配置、连接账号三类实体，沿用现有保存、验证、OAuth 接口。
4. 连接账号页保留管理功能，将新增流程改成单页表单。
5. 删除快速接入五步向导的重复实现，入口直接进入统一的认证实例创建表单。
6. 不新增数据库表、默认账号字段、组合后端接口、通用流程引擎或前端状态机库。

“默认账号”在本方案中指首次创建的账号，不新增运行时隐式选账号规则。API、同步任务和工作流仍通过明确的 connectionId 引用账号。

### 2.1 为什么不能直接把“测试成功”改成“连接成功”

现有实例检查使用 `authenticate`、`testCredentials`，调用 `TestInstanceToken`。测试凭据与返回令牌不会持久化。将按钮改名不会创建可用连接。

必须修改提交路径：实例保存 → 集成保存 → 账号凭据加密保存 → 正式连接验证。令牌获取、刷新和密钥隔离继续由现有 authn 服务负责。不要从临时测试响应复制 Token，也不要先临时登录再正式登录两次。

### 2.2 实例、集成与账号仍分别保存

- 实例：所属系统、认证模板、认证端点、Token 路径、注入规则、共享应用配置与应用密钥。
- 集成：所属系统、认证实例和 API 基础地址。
- 账号：账号名称、身份归属、账号凭据、Token、状态及验证记录。

用户名和密码不进入实例 publicConfig 或共享 secrets。共享 OAuth clientId/clientSecret 不重复存到每个账号。用户只操作一个表单，后台仍保持现有隔离与引用关系。

## 3. 页面与交互

### 3.1 新建认证实例

沿用当前完整实例编辑器，不复制到新弹窗。表单按以下顺序展示：

1. 基础信息：所属系统、实例名称、认证模板。
2. 认证配置：沿用当前各认证方式字段。
3. API 基础地址：明确输入目标 API 地址；验证接口路径继续属于实例配置。
4. 连接账号：账号名称与模板对应凭据。
5. 高级设置：实例标识、集成标识、账号标识、外部身份标识等。

底部主按钮按方式显示“保存并验证”或“保存并授权”。次按钮“仅保存配置”用于尚无账号或只创建共享实例的情况；次操作不要求账号凭据和 API 地址，只保存实例，不偷偷创建空账号。原“测试配置”可收进高级设置；原“测试认证”按钮删除。

主操作提交前一次校验所有必填项，校验失败不开始写入。草稿或禁用实例不能走正式创建连接路径，应提示保存配置或切换为可用状态。

账号名称可默认“服务账号”，允许修改。ID 隐藏到高级设置但仍可查看；不能把中文名称强制转换成可能冲突的标识。

### 3.2 复用已有实例

添加账号时优先选择现有集成；如现有实例还没有集成，提供“配置 API 地址并添加账号”的入口，使用同一账号表单与保存函数。

同一个实例存在多个集成时必须明确选择，不按照列表第一个自动绑定。创建新实例时集成自动创建；使用已有实例时只复用用户明确选定且系统、实例、地址匹配的集成。

集成页依然可以独立管理 API 地址与实例绑定，供多环境或多个 API 地址使用，但它不再是首次接入必经的页面。

### 3.3 编辑已有实例

- 普通“保存修改”只更新实例配置，不自动新增账号。
- 已有凭据不回显，不通过空密码覆盖已有秘密。
- 展示相关集成和账号的跳转入口；“添加账号”显式触发新的账号表单。
- 修改现有账号凭据在账号详情完成；保持已有 revision 冲突检测。
- 已有连接绑定的集成地址和认证实例仍受当前后端限制，不为精简界面绕过限制。

不能在编辑实例时默认修改某个账号：一个实例可能绑定多个账号，“第一个账号”不代表用户想修改的账号。

### 3.4 连接账号页面

保留列表、状态、筛选、详情、更新凭据、验证和现有管理操作。新增入口命名“添加账号”，打开一个单页表单：

- 集成选择：从指定集成进入时直接带入，无需再选一步。
- 账号名称与凭据。
- 高级设置中的外部身份标识。
- “保存并验证”或“授权连接”按钮。

删除 step 状态、三步指示器、上一步/下一步按钮、只读“允许的集成配置”、重复确认面板。所选集成展示为普通上下文信息。

“组织显示名”删除；确有外部身份显示名称需求时，在高级设置中称“身份显示名”。现有字段实际写入 endUserName，不代表组织实体。

### 3.5 快速开始与导航

- 快速开始按钮“接入系统”跳到 `/auth?section=instances&create=1`，可附带 system。
- `auth-methods.tsx` 解析 create 参数，数据加载后只打开一次；避免 reload 后再次重置用户输入。
- 原向导的系统创建需求通过现有系统页面处理；系统已选定则直接带入，不重新制作系统编辑器。
- 删除 `ConnectWizard` 引用和实现，首个 API 创建改为保存完成后的“创建 API”跳转，保留 integration 与 connection 上下文。
- `BuildFlow` 改为三个阶段“系统 → 接入 → API 验证”，沿用组件名即可，不新增第二个流程条。
- 快速开始不再把“实例、集成、账号”作为三个必须手动完成的步骤；管理页面入口仍保留。
- 更新概览、系统详情、集成页、API 页、快速开始中的旧创建按钮和说明，避免仍引导用户走已删除流程。
- 保留原路由与查询参数兼容；实例编辑器的 returnTo 不得在组合提交中途提前导航。

## 4. 最小代码组织

### 4.1 保留一个凭据渲染组件

`ConnectionCredentialFields` 继续作为唯一的账号凭据输入实现。实例创建与账号新增复用它，实例共享 secrets 区不混入账号密码。

对已有共享 clientId/clientSecret 的情况，字段校验应允许账号字段留空；这需要依据实际实例配置或已配置秘密的安全状态，而非页面显示名称猜测。前端不可见的已有秘密由后端验证，界面不要求重新填写。自定义模板继续按 credential schema 校验。

认证方式判断以 template key/flow 和后端能力为准。不要继续增加 `name.includes(...)` 分支；不支持的模板保持禁用。

### 4.2 一个账号提交函数

建议增加 `web/src/pages/connection-create.ts`，只包含账号保存/验证及 OAuth 启动的业务函数与少量类型。实例页与账号页共用，不引入 Hook 框架或通用 pipeline。

输入：明确的 integrationId、稳定 connectionKey/endUserKey、名称、凭据，以及已保存 connectionId（如有）。输出：已保存账号 ID、验证结果或 OAuth authorizationUrl。

调用方负责表单状态、通知、导航与刷新。函数不得吞掉异常返回 true/false，不在每个阶段重复 reload。

实例字段到 API 请求的映射留在现有位置；调整 `demo.saveAuthInstance` 返回实体，并区分保存与检查结果。必要时提取一个纯映射函数，不再复制 `connect-wizard.tsx` 的精简映射。检查所有原 boolean 调用方并一并更新。

组合创建只在实例页顺序调用现有接口，不再新建第二个公共“接入服务”。页面保存期间统一 pending 并在 finally 复位，防止双击与异常后按钮锁死。

### 4.3 刷新与成功提示

保存链路先记录服务器返回 ID，再刷新缓存。刷新失败表示数据展示未更新，不等同于创建失败，不重新发起 POST。一次操作统一提示最终结果，结束或失败后刷新必要的数据列表。

## 5. 提交流程与现有接口

### 5.1 非浏览器授权

```text
校验完整表单
  → POST /api/auth-instances（已保存则按需 PATCH）
  → POST /api/integrations（已明确复用则跳过）
  → POST /api/connections（已保存则重试验证或按 revision 更新）
  → POST /api/connections/{id}/verify
  → 刷新相关数据，展示结果与“创建 API”入口
```

实例仍传 systemId/authTemplateId，集成仍传 systemId/authInstanceId/baseUrl，账号仍传 integrationId、connectionKey、name、endUserKey、credentials。

自动生成标识使用一次生成的随机后缀，例如 `account-<uuid>`，在当前创建会话中稳定。默认 endUserKey 使用该账号自身标识，不使用同一个全局 `default`，也不使用实际用户名或密码。外部系统有稳定用户/租户 ID 时由高级设置显式填写。此值是归属标识，不能替代授权校验。

主流程不先调用 `check(...authenticate=true)`；正式 verify 已负责认证解析及需要的 Token 获取。结构检查可独立使用无写入 check。

### 5.2 OAuth2 授权码与 OIDC

```text
校验并保存实例与集成
  → POST /api/oauth/start
  → 跳转上游授权页面
  → 现有 callback 交换令牌并保存连接
  → 返回账号/接入结果页
  → 确认该连接存在，按需执行 verify，进入 API 创建
```

oauth/start 显式传入 integrationId、endUserKey、connectionKey、connectionName、returnPath；不用当前 `demo.startOAuth` 中临时生成标识的方式重建创建会话。共享函数直接复用 api.oauthStart，旧包装器只有无调用方时才删除。

OAuth 密码不在 Connara 表单输入。回调完成前不能宣称账号已创建或验证通过；取消授权保留已保存实例与集成，允许继续授权。沿用现有 state、PKCE、nonce、回调校验和工作区限制。

授权跨页面恢复只需要非敏感上下文（实例/集成 ID、账号标识、返回位置）；可放入受控 returnPath 或短期 sessionStorage。凭据、客户端密钥、令牌不得写入 URL 或浏览器持久存储。返回时以服务器记录为准，不信任本地“成功”标志。

### 5.3 各认证方式的结果文案

| 情况 | 界面结果 |
| --- | --- |
| 密码换 Token/客户端凭证成功，无验证路径 | “认证配置可用，账号已保存；尚未验证 API 权限” |
| API Key/Basic/无认证，无验证路径 | “账号已保存，配置检查通过；尚未验证上游访问” |
| 配置 verificationPath 且 GET 返回 2xx | “连接验证通过” |
| OAuth 回调成功，无 API 验证 | “授权完成；尚未验证 API 权限” |
| 凭据错误、令牌获取失败或验证接口失败 | 显示对应阶段错误，保留已保存对象并允许修正/重试 |

前端按 lastVerifiedAt 等服务器证据判断 API 验证通过，不以 HTTP 200 或账号 active 状态单独推断。现有 Resolve 在无验证路径时也可能完成 Token 获取；“未验证 API 权限”不等于“没有发出认证请求”。本轮不新增精细认证状态字段；只有确有服务器证据时显示“登录成功”。

## 6. 失败恢复与重复提交

采用现有接口的顺序提交，整体不是一个数据库事务。实例、集成可能先保存成功；产品必须明确显示这些部分成功，不能用“全部失败”掩盖实际写入。

| 失败位置 | 恢复行为 |
| --- | --- |
| 前端校验 | 不写入，保留输入，定位字段 |
| 实例保存 | 不创建集成或账号 |
| 集成保存 | 记录已保存实例 ID，修正后从集成开始 |
| 账号保存 | 保留实例与集成 ID，修正后仅重试账号保存 |
| 账号验证 | 保留 connectionId，仅验证；修改凭据则 PATCH 原连接并携带 revision |
| 刷新列表 | 提示展示刷新失败，保留创建成功状态与 ID |
| OAuth 取消/失败 | 复用原集成与账号标识重新授权，不能自动创建新实例 |

只需保存 instanceId/integrationId/connectionId 及当前阶段错误，不引入枚举驱动流程框架。发生部分保存后，锁定系统、模板、绑定和地址等会改变对象关系的字段；如要改变这些字段，显式开始新的接入，不把旧连接偷偷移动到新集成。

对超时或响应丢失，不能假定服务器没有写入。通过本次稳定 key 查询已有对象并核对绑定：匹配则继续，发现不匹配则显示冲突。优先复用现有列表/详情接口与唯一约束；实施时确认分页覆盖与 lookup 能力，仅在无法可靠查询时增加最小的按 key 查询能力。禁止冲突后直接 PATCH 不明来源的记录。

UUID 只解决标识冲突，不等同于端到端幂等。验收必须覆盖“服务器已提交但客户端未收到响应”的重试。关闭表单后凭据清空；再次进入通过已有对象管理入口继续，不缓存密码实现恢复。

不自动删除部分成功对象：它们可能已被引用。账号验证错误是否持久化沿用现有能力；若当前没有记录错误，不宣称列表一定能显示具体原因，错误至少保留在当前表单。

## 7. 删除与保留清单

### 7.1 应删除

- 实例编辑器的 testCredentials 状态、手写“测试用户名/密码”渲染、仅供页面临时认证的 authenticate 提交参数。
- 实例页“测试认证”按钮和“测试凭据及令牌不保存”的旧说明，替换为正式保存凭据说明。
- 连接新增三步向导的 step 状态、下一步/上一步逻辑、确认页和无操作意义的只读字段。
- `connect-wizard.tsx`、只服务于它的测试和状态/导入；有效场景迁移到统一流程测试后再删除。
- 快速开始重复创建对象的入口，以及旧五步手动配置引导。
- `demo.addConnection`、旧 OAuth 包装等重复保存函数：先搜索引用，统一调用后才删除。
- 孤立翻译键、无引用组件、无引用图标与样式；需全局确认使用情况。

### 7.2 必须保留

- 认证模板编辑与系统绑定、完整实例配置及高级协议字段。
- 实例/集成/账号实体、已有数据与稳定 ID；不改现有引用关系。
- 账号列表/详情/凭据更新/验证、多个账号与多个集成的管理能力。
- 后端加密、审计、写权限检查、出站限制、OAuth 校验、version/revision 冲突机制。
- 旧实例 check 的临时认证能力：本轮删除前端使用，服务端暂保留，避免为小范围 UI 精简删除尚未明确弃用的 API。后续独立确认无消费者再清理。

精简以消除重复流程与重复实现为准，不以删掉必要能力或压缩代码行数为准。不得新建与旧页面并行的一套“精简版”接入页面。
